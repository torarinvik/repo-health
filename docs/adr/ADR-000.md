# ADR-000 — Implement repo-health in Elisa (override plan default)

**Date:** 2026-09-18
**Status:** Accepted (goal-driven; owner ratification pending for license choice)
**Context:** IMPLEMENTATION_PLAN.md §1.4 proposes Rust + PostgreSQL + filesystem
content-addressed storage + server-rendered web UI as the default technical
direction, and states "Elisa is not a prerequisite for shipping repo-health"
and that changing to Go is acceptable if deliberate with the same safety/test
contracts.

**Decision:** The active goal (`/goal implement the entire plan in
IMPLEMENTATION_PLAN.md in Elisa programming language`) overrides the default:
the reference implementation in this repository is written **entirely in the
Elisa programming language** (`*.elisa` sources) and built with the
self-hosted Elisa compiler in the sibling `Elisa-compiler` folder
(product entry `src/driver/elisac.elisa`, host CLI
`scripts/elisac_stage1.sh` wrapping `bin/elisac-stage1`, semantic gate ON).

**Rationale:**
- The goal explicitly requires Elisa; the plan itself permits a deliberate
  language change before the domain grows, provided safety/test contracts hold.
- Elisa's semantic gate (name resolution, typecheck, effects `can[...]`,
  ownership/regions) gives a strong foundation for the plan's
  unknown-!=zero and bounded-resource invariants.
- Single-language reference keeps the evidence-first contracts auditable.

**Consequences:**
- All domain, metric, evidence, CLI, and test-oracle code lives in
  `src/*.elisa`, compiled via `tools/build.sh` (no Rust toolchain required).
- POSIX C bridges (`extern` for `system`, `fopen/fread/fwrite/fclose`,
  `puts`, `argv`) are the only native boundary; each bridge is documented
  and tested (notably: `system(3)` invokes a shell, so `rh_git.elisa`
  enforces a strict allowlist + metacharacter rejection before any call —
  see Threat Model `docs/THREAT_MODEL.md`).
- Persistence starts as filesystem evidence bundles + JSON reports (per plan
  §1.5 minimal stack); a PostgreSQL-compatible projection remains an
  interface option, not a requirement for M00/M01.
- Performance claims are measured with the Elisa benchmark harness, never
  assumed from Rust figures.

**Toolchain pin (see TOOLCHAIN.md):** `bin/elisac-stage1` product binary
(seeded once via `--seed`), LLVM 23.1.1 (`/opt/homebrew/opt/llvm`), Apple
`clang` link with `-Wl,-dead_strip` + `build/runtime/elisacore_runtime.o`.
No `latest` tags in automation.
